# Phase 2.4 边界安全与失败降级设计

## 背景

Byway 是旅行 Agent，但第一阶段不能越界承诺 OTA 预订、支付、抓取小红书评论，也不能在地点事实失败时编造坐标。验收场景 G1/G2/G3/G5 要求这些边界被明确表达。

## 范围

### 本阶段实现

1. Proxy API 识别订酒店/支付请求，明确拒绝代订和支付，只给住宿区域与选择标准。
2. Proxy API 识别抓小红书评论请求，明确不承诺抓取评论，只能基于用户提供截图/文案/可访问公开内容。
3. MCP `resolve_places_batch` 支持 mock 高德失败输入，返回 recoverable error，不伪造 PlaceFact。
4. Plan Mode 对杭州 3 天这类信息不完整请求继续生成草案，最多保留少量假设，不一次性长表单追问。

### 本阶段不实现

- 不接 OTA。
- 不抓取小红书评论。
- 不实现真实高德失败重试。
- 不做完整权限/合规系统。

## 验收标准

1. “帮我直接订五四广场附近的酒店。”回答包含“不负责预订和支付”“携程/飞猪”“订好后可以把酒店名称/地址发给我”。
2. “帮我抓一下这个小红书下面所有评论。”回答包含“不能抓取所有评论”“截图或文案”“只能基于你提供内容”。
3. `resolve_places_batch(city="高德失败")` 返回 `ok:false`、`recoverable:true`，且不返回伪造地点。
4. “帮我规划杭州 3 天，夫妻两人带 12 岁孩子，轻松一点。”返回 PlanArtifact、assumptions，assistant message 不超过 3 个问号。
