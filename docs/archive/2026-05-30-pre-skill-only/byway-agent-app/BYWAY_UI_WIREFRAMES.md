# Byway / 另辟蹊径 — 移动端 UI 线框图

---

## 1. UI 总原则

Byway 的 UI 不是传统 App。

核心形态：

```text
聊天窗口 + 动态旅行 Artifact
```

用户不需要：

- 逐个管理地点。
- 审核每个节点。
- 填大量表单。
- 在复杂 Tab 中切换。

用户只需要：

- 说出目的和偏好。
- 粘贴攻略、链接、截图。
- 在旅行中反馈突发事件。
- 对关键变更点击确认。

---

## 2. 页面结构总览

```text
┌──────────────────────────┐
│ Trip Header              │
├──────────────────────────┤
│ Artifact Panel           │
├──────────────────────────┤
│ Chat Thread              │
├──────────────────────────┤
│ Input Composer           │
└──────────────────────────┘
```

移动端上 Artifact Panel 可以：

- 嵌在聊天流中。
- 或作为可折叠卡片。
- 或底部浮动半屏。

不要做复杂全屏管理后台。

```text
│ 我先按 6 人全家、轻松节奏、 │

├──────────────────────────┤

│ ┌──────────────────────┐ │
│ │ 青岛                  │ │
│ │ 适合度：9/10          │ │
│ │ 推荐天数：4 天         │ │
│ │ 适合：老人孩子 / 海边   │ │
│ │ 风险：暑期人多、酒店贵  │ │

│                          │

│ │ 适合度：8/10          │ │

├──────────────────────────┤
```

### UI 要点

- 候选数量控制在 3-5 个。
- 每张卡片只显示决策关键点，不展示完整攻略。
- 必须有“为什么不推荐/主要风险”。
- 选择目的地是高影响动作，需要确认或明显按钮。

```text
├──────────────────────────┤

├──────────────────────────┤
│ 计划摘要                   │
│                          │
│ 住宿建议：                 │
│ 首选 五四广场/奥帆中心      │
│ 备选 老城区                │
│                          │
│ 用餐区域：                 │
│ Day 1 酒店附近             │
│ Day 2 老城区/五四广场       │
├──────────────────────────┤
│ Day-by-day                │
│ Day 1 抵达 + 酒店附近轻活动 │
│ Day 2 老城 + 八大关         │
│ Day 3 崂山轻量版 / 市区备选 │
│ Day 4 海边收尾 + 返程       │
├──────────────────────────┤
│ 需要确认                   │
│ - 第一天几点到？            │
│ - 第四天几点走？            │
│ [确认计划] [继续调整]        │
├──────────────────────────┤
│ [ 继续告诉我你的想法...     ]│

```

### UI 要点

- 用户不需要手动编辑每个 DayNode。
- 用户可以说：“Day 3 不想去崂山，太累了。”
- Agent 通过 MCP 工具更新计划。
- 如果计划有低置信度地点，要以自然语言提示。

```text
│ 2. 青岛老街 B，市北区        │
│                          │

└──────────────────────────┘
```

### UI 要点

- 不要展示所有 POI 表格。
- 只展示需要用户确认的低置信度核心地点。
- 普通低优先级地点可以仅作为 warning。

## 12. 输入框设计

```text
┌──────────────────────────┐
│ [ + ] [ 说说你的情况...    ]│
│       [发送]               │
└──────────────────────────┘
```

`+` 支持：

- 上传截图。
- 上传 markdown 文件。
- 粘贴链接。
- 粘贴长文本。

快捷建议根据状态变化：

Dream：

```text
[国内优先] [海边] [轻松一点] [预算中等]
```

Plan：

```text
[补充酒店] [补充交通] [不要太累] [更亲子]
```

Travel：

```text
[晚了] [老人累了] [孩子累了] [饿了] [下雨]
```

Review：

```text
[今天结束] [补充感受] [生成总结]
```

## 13. 视觉优先级

移动端屏幕有限，优先级：

1. 当前 Agent 回复。
2. 当前关键 Artifact。
3. 输入框。
4. 历史聊天。

不要让历史聊天挤掉当前计划卡片。

---

## 14. 前端不该出现的界面

不要做：

```text
地点列表管理页
PlanNode 表格编辑器
复杂 POI 审核后台
大量字段表单
多 Tab 旅行管理系统
全量攻略数据库视图
```

如果需要用户确认，只做小卡片确认。

---

## 15. UI 验收标准

- 用户能在手机上单手输入。
- 用户能一眼看到当前旅行状态。
- 旅行中能一眼看到当前和下一个节点。
- 调整方案能看懂差异。
- 用户不需要学习复杂操作。
- 所有关键确认都有明确按钮。
