# Byway Memory Policy

仅当 Hermes 已接入可按需查询和更新的外部 memory provider 时，才参考本文件。主 Skill 不依赖本文件完成普通旅行对话。

## 原则

- Hermes 内置 `memory` / `user` 不是旅行状态库。
- 单次旅行计划、当前进度和临时事件不写入 Hermes 内置 memory。
- 外部 provider 可保存跨会话旅行记录，但只保存摘要和关键节点。
- 可变状态更新旧记录，不每轮新增。
- 未确认事实和未确认偏好不得作为确定记忆保存。

## 外部 Provider 内容

可保存：

- `trip_record`：旅行名称、目的地、开始/结束时间、状态、同行人、节奏。
- `living_plan_snapshot`：当前活计划摘要和更新时间。
- `key_nodes`：抵离、住宿、预约、必须保留活动、已确认的重要修改。
- `current_progress`：当前进行到哪一天、哪个节点、正在讨论什么。
- `trip_learning`：旅行结束后有复用价值、且用户确认的经验。

不要保存：

- 完整攻略原文。
- 长日志或大段对话摘要。
- 临时天气、排队、晚点等一次性现场事件。
- 未确认地点事实。
- 用户随口探索的临时想法。

## Provider 偏好

若可用，优先使用 Holographic 这类本地、按需、可更新的事实存储。不要开启会把所有对话自动抽成旅行记忆的策略。

## Hermes 内置 Memory

Hermes 内置 `user` 只写入用户确认过的稳定家庭旅行偏好，例如“不喜欢太赶”“父母下午需要休息”。

Hermes 内置 `memory` 只写入 Byway 工作规则或项目级事实，不写入单次旅行计划、当前进度或临时事件。
